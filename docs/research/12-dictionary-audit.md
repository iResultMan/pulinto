# Аудит расширенных словарей

Проверка расширенных словарей (заказчик подготовил их отдельно) на отложенном
корпусе `docs/research/corpus2/heldout.tsv`, 21 300 слов реального текста.

## Итог: расширение ухудшило работу

| | прежние словари | расширенные | изменение |
|---|---|---|---|
| Точность | 99,26% | 98,87% | −0,39 |
| **Ложные срабатывания** | **0,06%** (9 слов) | **0,61%** (95 слов) | **в 10 раз хуже** |
| Пропуски | 2,58% | 2,53% | −0,05 |
| Слова из 3 букв | 99,0% | 95,8% | −3,2 |

Обмен получился невыгодным: полнота выросла на пять сотых пункта, аккуратность
упала более чем в десять раз. По принятому в проекте принципу ложное
срабатывание дороже пропуска (§1.2 спецификации), это регресс.

## Что именно ломается

92 из 95 ложных срабатываний происходят на словарной ступени, 84 из 95 — на
словах из трёх букв. Почти все — латинские акронимы, превращённые в кириллическую
бессмыслицу:

```
ATP → ФЕЗ    PDF → ЗВА    BBC → ИИС    RPG → КЗП
ERR → УКК    XDC → ЧВС    UFC → ГАС    CVV → СММ
```

## Корень проблемы — не объём, а недостоверность частот

Объём сам по себе не приговор. Приговор — то, что частоты перестали отражать
употребимость.

**Признак первый: частота 1 как заглушка.** 75% русских записей (3,35 млн из
4,47 млн) имеют частоту ровно 1, при этом записей с частотой 2 нет **вообще**.
Такое распределение невозможно для подсчёта по корпусу; это подпись объединения
источников, где словарю словоформ без частотных данных проставили единицу.

**Признак второй: пакетно проставленные значения.** У кириллического мусора,
победившего акронимы, частоты неправдоподобно велики и повторяются:

| строка | «частота» |
|---|---|
| `гас` | 112 151 |
| `иис` | 101 871 |
| `ппп` | 84 948 |
| `чвс` | 61 522 |
| `зва` | 52 069 |
| `смм` | 52 069 |
| `кзп` | 50 000 |

Совпадающие до единицы значения у `зва` и `смм` и ровно круглое 50 000 у `кзп`
означают, что числа назначены, а не посчитаны.

**Следствие.** Весь наш алгоритм третьей ступени построен на сравнении частот с
запасом (§11, этап B плана). Когда частота недостоверна, сравнивать нечего:
`ИИС` со «частотой» 101 871 выигрывает у любого настоящего английского акронима.

**Признак третий: насыщение коротких строк.** В русском словаре 9 809
трёхбуквенных записей из 32 768 теоретически возможных — то есть **30% всех
мыслимых трёхбуквенных сочетаний объявлены словами**. Любой трёхбуквенный
латинский акроним с вероятностью около трети попадает в «известное русское
слово».

## Пороги проблему не решают

| пороги (2-букв, 3-букв, 4-букв, запас) | точность | ложные | пропуски |
|---|---|---|---|
| текущие `1000, 0, 0, 4` | 98,87% | 0,61% | 2,53% |
| `1000, 50000, 0, 4` | 98,82% | 0,48% | 3,11% |
| `1000, 150000, 0, 4` | 99,03% | 0,08% | 3,40% |
| `5000, 150000, 50000, 4` | 98,65% | 0,08% | 4,82% |

Лучший достижимый вариант (99,03% при 0,08% ложных) всё равно **хуже прежних
словарей по всем показателям сразу**: там было 99,26% при 0,06% и 2,58%
пропусков. Поднимая порог, мы отсекаем мусор вместе с настоящими словами.

## Что нужно менять в алгоритме

Если расширенные словари остаются, потребуется следующее.

**1. Перестать доверять абсолютным частотам.** Пороги `min_frequency`,
`acronym_min_frequency` и `margin` калибровались под корпус, где максимум был
около 500 тысяч, а словарь содержал 163 тысячи слов. Сейчас максимум русского —
500 005, английского — 1 764 495, то есть шкалы разошлись **между языками**, и
одно абсолютное число не может быть верным для обоих. Переходить надо на
относительную меру: ранг слова или частота на миллион токенов.

**2. Считать частоту 1 отсутствием данных, а не редкостью.** Сейчас такое слово
проигрывает любому сопернику по запасу в четыре раза. Для 3,35 млн русских
словоформ это означает систематическое поражение настоящих русских слов.

**3. Защиту акронимов строить не на частоте.** Порог `acronym_min_frequency`
бессилен, когда у мусора частота 112 тысяч. Нужен отдельный выверенный список
допустимых коротких форм, а не порог по общему словарю.

**4. Пересмотреть бюджет памяти.** Данные выросли с 2,2 МБ до **23 МБ**
(`ru.fst` 19 МБ, `en.fst` 3,8 МБ) при заявленном бюджете резидентного демона
6 МБ. Загрузка через `mmap` вместо чтения в память становится обязательной, а не
желательной.

**5. Мёртвые данные.** Появились `data/dict/it.*` и `data/languages/it/`, но в
`crates/pulinto-core/src/layout.rs` заведены только две раскладки — `us` и `ru`.
Профиль для `it` не строится, файлы не используются.

## Рекомендация

**Вернуться к прежним словарям** (162 994 русских слова, 106 202 английских) и
расширять их выборочно: добавлять только те источники, для которых есть
достоверные частоты, посчитанные единым способом по одному корпусу.

Если расширенные словари нужны по другим причинам, минимально необходимое —
пересчитать частоты заново по единой методике для всех источников. Без этого
третья ступень каскада, принимающая три четверти всех решений, работает на
недостоверных данных.
