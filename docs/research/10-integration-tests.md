## Стенд

Готовый инструмент уже был в дереве и не пришлось изобретать заново:
`crates/pulinto-input/examples/kbharness.rs` — фикстура для ровно этого
сценария. Собран `cargo build --release --example kbharness -p pulinto-input`,
бинарь: `target/release/examples/kbharness`.

- `kbharness send <script>` — создаёт виртуальную клавиатуру через
  `/dev/uinput` с именем `PuLinTo Test Fixture Keyboard` (сознательно НЕ
  `PuLinTo Virtual Keyboard`, чтобы демон не проигнорировал её как своё же
  выходное устройство — см. `crates/pulinto-input/src/capture.rs:36,60`) и
  проигрывает мини-скрипт скан-кодов (`type:`, `key:`, `hold:`, `combo:`,
  `sleep:`).
- `kbharness sniff <ms> [device]` — открывает устройство демона
  (`PuLinTo Virtual Keyboard`, `capture::VIRTUAL_DEVICE_NAME`) на чтение и
  печатает каждое событие с декодом под раскладками `us`/`ru`, сегментируя
  вывод по паузам > 300 мс. Даёт и таймкоды (`t=`), и wall-clock (`wall=`) —
  вторые используются для замера задержки разделителя между процессами
  `send` и `sniff`.
- `kbharness grabcheck [device]` — доказывает, что демон реально снял
  `EVIOCGRAB` (не просто написал в лог): пытается захватить устройство сам;
  успех = демон отпустил, `EBUSY` = всё ещё держит.

Управление демоном — по D-Bus (`busctl --user call ru.pulinto.Daemon1
/ru/pulinto/Daemon1 ru.pulinto.Daemon1 <Method> ...`), интерфейс из
`crates/pulintod/src/dbus.rs`. Конфиг: `~/.config/pulinto/config.conf`
(`mode`, `auto_enabled`, тайминги §11.4 ALGORITHM.md).

Запуск демона:
```
cd "/home/medushenko/dev/PuLinTo"
nohup setsid ./target/release/pulintod > .../pulintod-test.log 2>&1 < /dev/null & disown
```

Внешний сторож (`deadman.sh`, уже был запущен параллельным процессом) снимет
захват через 2 часа принудительно — это страховка, не план работы.

`ibus`-движок (`ibus/pulinto_ibus.py`) тестировался без установки в систему:
класс `PulintoEngine` наследует `IBus.Engine`, но вся бизнес-логика

#### Дефект №1 (наблюдение, серьёзный): автоповтор дублирует буквы в `observe`

`crates/pulinto-input/src/capture.rs:90-108` (`start()`) читает `/dev/input`
напрямую и для любого события клавиши вычисляет `pressed = event.value() != 0`
— то есть `value == 2` (автоповтор ядра) тоже считается «нажатием» и уходит в
канал. `crates/pulintod/src/engine.rs::handle_capture_event` не отличает
автоповтор от обычного нажатия вообще (нет проверки `event.value()`), поэтому
`wb.push_char(ch)` вызывается на каждое повторное событие — буква
дублируется в словарном буфере.

Контраст: `crates/pulinto-input/src/grab.rs:158-167` (`key_transition`,
используется режимом `grab`) как раз для этого возвращает `None` на
`value==2`, с комментарием в коде: «Feeding those into the word buffer
duplicates letters, which is exactly the "letters get doubled" symptom users
report». Тот же самый защитный код в `grab.rs` для `observe` просто не
подключён — `capture.rs` и `engine.rs` используют собственный путь без этой
проверки. Прямое противоречие `docs/ALGORITHM.md` §11.6 («Автоповтор
игнорировать... Их нужно отбрасывать на входе»), которое там сформулировано
как общее требование, а не как особенность только режима `grab`.

Шаги воспроизведения: режим `observe`, зажать любую буквенную клавишу
(автоповтор ОС/ядра начинает слать `value=2`), отпустить, дописать слово так,
чтобы без дублирования оно совпадало со словарной статьёй в неверной
раскладке, поставить пробел — конверсия не происходит, потому что слово в
буфере уже не то, что напечатано визуально. В более общем случае, при простом
наборе с удержанием (не только тестовый `hold:`), это даёт классический
глюк Punto «ккккомпьютер».

### Блок 3 — `grab` (основной режим)

**Важная методологическая находка по ходу теста.** Каждая успешная конверсия
вызывает `layout.toggle_next()` — а это **реальный** X11 XKB `group`
(`crates/pulinto-layout/src/x11.rs:35-43`, живой XKB через X11-расширение, не
макет). То есть тестовый прогон необратимо переключает **настоящую**
раскладку сессии туда-сюда при каждой удачной конверсии, и слово, которое
было "неверной раскладкой" для сценария N, оказывается уже нормальным словом
к сценарию N+1, если N успешно сконвертировался. Один из ранних прогонов
блока (использовавший `ghbdtn` семь раз подряд без учёта этого) дал 0
конверсий вообще — не потому что что-то сломано, а потому что реальная
раскладка после предыдущего блока (`observe`) уже была `ru`, и `ghbdtn` под
`ru` — это уже готовое `привет`, править нечего. После того как это было
замечено, слова для сценариев были подобраны так, чтобы соответствовать
фактическому текущему `group` в момент сценария (проверено через
`Status.conversions` до/после и раскодировкой `kbharness sniff` в обе
стороны), а не искусственно навязанному «раскладка всегда `us`».

Синхронизация со стендом: та же схема polling через `kbharness grabcheck`
(ждём, пока попытка захватить фикстуру самим начнёт возвращать `EBUSY` —
значит демон её захватил после рестарта), затем `kbharness sniff` на
`PuLinTo Virtual Keyboard` параллельно с фоновым опросом `Status` каждые
400 мс для отслеживания счётчика `conversions`.

| Сценарий | Ожидалось | Получено (по проводу и логу) | Вердикт |
|---|---|---|---|
| слово + пробел → замена, разделитель после | замена, потом пробел | Провод: `t,e,s,t` (живой набор) → 4×Backspace(14) → `t,e,s,t` (повтор) → `SPACE`(57) последним. Задержка (нажатие пробела на фикстуре → появление пробела на выходе): **190 мс** для 4-буквенного слова | ПРОЙДЕНО |

**Нюанс, не дефект: аварийное снятие захвата — по устройству, а не глобально.**
`grab_engine::run()` — это цикл на одну клавиатуру (`crates/pulintod/src/main.rs:217-224`
запускает отдельный поток на каждое устройство). Паника-комбо, нажатое на
клавиатуре A, освобождает захват только клавиатуры A; клавиатуры B и C
остаются захваченными демоном. Для пользователя с одной физической
клавиатурой это ровно то, что нужно; с несколькими — стоит явно
задокументировать в пользовательской части, иначе аварийное сочетание может
создать ложное ощущение полного освобождения.

### Блок 4 — `ibus`

Проверено без установки движка в систему и без `ibus-daemon`: демон переведён
в режим `ibus` по D-Bus (лог подтвердил: `Ввод обрабатывает движок IBus.

## Известный дефект — воспроизведение (не чинить)

**`Abbreviation` держит любое слово из заглавных, а не только настоящие
аббревиатуры.** `crates/pulinto-core/src/stop_rules.rs::looks_like_abbreviation`
(ступень 0 каскада) — `letters.len() >= 2 && letters.iter().all(is_uppercase)`:
блокирует конверсию для ЛЮБОГО слова целиком в заглавных, включая случай,
когда пользователь просто не переключил раскладку и слово целиком набрано
Caps/Shift-Lock. Настоящие аббревиатуры (`NASA`, `СССР`, `ГОСТ`) каскад и без
этого правила не трогает — они не встречаются как словарные статьи в другом
языке и проваливают биграммную/триграммную проверку одинаково что с
правилом, что без него, так что защита существует только на бумаге, а на
практике глушит легитимные заглавные слова.

Воспроизведено на уровне каскада (`Judge` по D-Bus) и на уровне IBus-движка
(идентичный результат):

```
busctl --user call ru.pulinto.Daemon1 /ru/pulinto/Daemon1 \
  ru.pulinto.Daemon1 Judge sss "ТФЫФ" "" "ru"
→ {"convert":false,"text":"ТФЫФ","layout":"ru","stage":"StopRule"}
```

`ТФЫФ` — это ровно физические клавиши `N,A,S,A` (коды 49,30,31,30), но
набранные с зажатым Shift на русской раскладке (позиции по
`crates/pulinto-core/src/layout.rs`: N→т, A→ф, S→ы, A→ф, с сохранением
регистра через Shift даёт `ТФЫФ`). Пользователь, скорее всего, пытался
напечатать `NASA` заглавными (например, `Caps Lock` включён, а раскладка
осталась русской) — конверсия нужна, но `Abbreviation` останавливает её
раньше, чем до неё доходит очередь: ступень 0 срабатывает первой в каскаде
(§2 ALGORITHM.md), и ни ступень 3 (словарь), ни 4/5 (n-граммы) не получают
шанса решить, что перед ними на самом деле мусор, а не настоящая
аббревиатура.

Тем же способом воспроизведено через `ibus_test.py` (раздел 6b выше):
`type_word("ТФЫФ")` + пробел → `committed == 'ТФЫФ '`, движок не
конвертирует. Идентичное поведение в `grab`/`observe` ожидаемо, так как все
три фронтенда проходят через один и тот же `cascade::decide`.

Не исправлено намеренно, по заданию — фиксация для последующей правки
(вероятное направление: сузить `looks_like_abbreviation` до слов, которые
одновременно (а) целиком заглавные и (б) не совпадают ни с одной словарной
формой ни в одном языке после приведения к нижнему регистру и конверсии —
тогда `NASA`/`СССР` остаются защищены, а `ТФЫФ`/`NASA-опечатка-раскладкой`
получает шанс дойти до словарной ступени).

### Дефекты по убыванию серьёзности

1. **[Серьёзный, новый] Автоповтор дублирует буквы в `observe`.**
   `crates/pulinto-input/src/capture.rs` не фильтрует `value==2` (в отличие
   от `crates/pulinto-input/src/grab.rs::key_transition`, где ровно эта
   защита есть и явно прокомментирована). Держите букву — слово в буфере
   `observe` разъезжается со словом на экране, и ожидаемая конверсия не
   срабатывает. Воспроизведено дважды на одном и том же сценарии.
2. **[Известный, не чинить] `Abbreviation` стоп-правило слишком широкое.**
   `crates/pulinto-core/src/stop_rules.rs::looks_like_abbreviation` блокирует
   любое слово целиком в заглавных, а не только настоящие аббревиатуры.
   Воспроизведено и на каскаде (`Judge`), и на IBus-движке: `ТФЫФ`
   (физически `NASA` заглавными на ru) остаётся нетронутым.
3. **[Нюанс, не дефект] Аварийное снятие захвата — по устройству.**
   Комбо `Backspace+Esc+Enter`, нажатое на одной клавиатуре, не освобождает
   остальные захваченные устройства демона. Верно и ожидаемо для типичного
   пользователя с одной клавиатурой, но стоит явно задокументировать.
