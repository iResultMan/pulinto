# Отчёт о тестировании окна настроек `gui/pulinto-settings`

Дата: 2026-10-16. Окружение: GTK 4.22.4, libadwaita 1.9.1, PyGObject 3.56.2, Python 3.14.4.
Окно запускалось на отдельном X-сервере `Xvfb :91` (1280×900, `GDK_BACKEND=x11`, без `WAYLAND_DISPLAY`),
с настоящей сессионной шиной и настоящим демоном `pulintod` (pid 2258576, режим `grab`).
Управление — через AT-SPI (`gi.repository.Atspi`); снимки — `import -display :91 -window root`.
Ничего через окно не сохранялось: демон до и после (`daemon-state-before.txt`, `daemon-state-after.txt`) совпадает.

Файлы в этом каталоге: `NN-*.png` — снимки, `gui-stderr.log` — stderr окна за весь сеанс,
`a11y.py`/`act.py`/`nav.py`/`leak.py`/`resize.py`/`xt.py` — скрипты, которыми велась проверка.

## Что проверено и работает

- Запуск с работающим демоном: окно открывается за ~2 с, все восемь разделов боковой панели переключаются
  (`02-page1..7.png`), счётчик «Приложения 1» совпадает с `ListEnabledApps` = `['com.anthropic.claude']`.
- Состояние в «Обзоре» совпадает с `Status`: режим «Захват» = `grab`, «0 исправлений» = `conversions: 0`,
  переключатель «Исправлять автоматически» включён = `auto_enabled: true`, «Служба — Работает» = `status: running`.
- «Клавиатура»: «Apple — найдена», переключатель включён, «us(mac), ru(mac)» — совпадает с `KeyboardInfo`
  (`apple_keyboard: true, apple_layout: true, layouts [us, ru], variants [mac, mac]`). Баннеров нет — верно
  (`can_apply: true, foreign_variant: null, restart_needed: false`).
- «Горячие клавиши»: оба набора, все привязки и подписи клавиатур совпадают с `GetHotkeys`
  («System Administrator’s Keyboard — Apple; solaar-keyboard — PC; Logitech K520 — PC»); кнопка «Сбросить набор»
  неактивна, потому что все `is_default: true`. (Диалог записи сочетания не открывался: он захватывает
  клавиатуру живой сессии через `RecordHotkey`.)
- Пустые состояния «Автозамены», «Не менять», «Всегда менять» (`02-page1..3.png`); блок «Забытые слова» скрыт при
  `ForgottenWordCount = 0`.
- Диалоги добавления (все четыре): открываются, фокус в первом поле, «Сохранить» неактивна при пустом или
  пробельном «Что набрано»/«Слово»/«Приложение», активна при заполнении; предпросмотр «Станет» в «Всегда менять»
  даёт `ghbdtn → привет` (через `PreviewLayoutConversion`); Юникод (эмодзи, RTL, CJK, комбинируемые знаки)
  отображается корректно (`05-dlg-unicode.png`); «Отмена» закрывает без обращения к демону.
- Утечки: 15 циклов «открыть диалог → Отмена» — RSS 267 → 300 МБ после 10 циклов и дальше не растёт (кэш GTK),
  в дереве AT-SPI после закрытия диалогов нет; число открытых fd не меняется (26).
- Поиск: «zzz» на странице «Приложения» прячет все строки и показывает «Ничего не найдено» в обоих списках
  (`11-search-zzz.png`). Пустая строка возвращает всё.
- Меню (`17-menu.png`): «Справка и горячие клавиши» открывает «Справку»; «Обновить списки» показывает тост
  «Списки обновлены» (`26-refresh-toast.png`). Акселераторы `Ctrl+R`/`F1` в меню отображены.
- Узкое окно 500 px и минимальное 360×360: NavigationSplitView схлопывается в один столбец, показана боковая
  панель (`13-narrow-500.png`, `15-min-360.png`); 1280×900 — содержимое ограничено Clamp, пустоты распределены
  (`16-wide-2500.png`). Горизонтальной прокрутки нет.
- Закрытие кнопкой «Закрыть»: процесс завершился за 0,87 с, без трассировок; имя `ru.pulinto.Settings` с шины ушло.
- stderr за весь сеанс (`gui-stderr.log`): трассировок нет; одно предупреждение Adwaita (см. находку 1); остальное —
  шум окружения (libEGL/DRI3 из-за Xvfb, PyGObject/asyncio deprecation из `gi/events.py`, не из кода окна).

Не удалось проверить: нажатия клавиш (`Ctrl+F`, `Ctrl+N`, `Delete`, `Esc`, `Enter`) — XTest-события до окна GTK4 на
Xvfb без оконного менеджера не доходят (проверено набором «abc» в поле: текст не появился), а
`Atspi.generate_keyboard_event` ввёл бы клавиши в живую сессию. Акселераторы проверены косвенно через меню.
Диалоги импорта/экспорта — см. находку 7.

## Находки

### 1. ВАЖНО — Диалог «Всегда менять» с длинным словом разъезжается на 38 000 px, «Сохранить» недоступна

Шаги: «Всегда менять» → «Добавить слово» → вставить в «Слово» строку из ~4800 символов (`ghbdtn`×800).
Факт: диалог растягивается на всю ширину и за пределы окна; заголовок «Станет» переносится по буквам
«С-т-а-н-е-т», кнопка «Сохранить» и правая часть полей за пределами экрана (`09-dlg-always-long.png`);
в stderr: `Adwaita-WARNING: AdwFloatingSheet 0xe455c50 exceeds AdwBreakpointBin width: requested 38615 px, 930 px available`.
Ожидалось: предпросмотр обрезается многоточием, диалог остаётся 460 px.
Причина: `gui/pulinto-settings:674` — `preview_value = Gtk.Label(xalign=1, …)` без `ellipsize`/`max_width_chars`
(в отличие от `value_label` для области в строках списка, строки 494–496, где `Pango.EllipsizeMode.END` стоит).
Аналогичный диалог «Автозамены» с теми же 4800 символами держит ширину (`04-dlg-long.png`) — там поля `Adw.EntryRow`.
Длинное слово реалистично при вставке из буфера.

### 2. ВАЖНО — Фильтр поиска остаётся после смены страницы, список выглядит пустым без признаков поиска

Шаги: «Приложения» → лупа (Ctrl+F) → ввести «zzz» → перейти в «Автозамены» → вернуться в «Приложения».
Факт: строка поиска закрыта, но оба списка по-прежнему показывают только «Ничего не найдено»; счётчик в
боковой панели «1» и заголовки «Ваши правила»/«По умолчанию» на месте (`12-search-stale.png`). Ctrl+R не помогает —
фильтр переживает `refresh()`. Сброс только повторным вводом поиска на этой странице.
Ожидалось: при уходе со страницы её фильтр сбрасывается.
Причина: `on_sidebar_selected` (строка 1855) сначала ставит `self.current = page` (новая страница), а потом
`self.search_button.set_active(False)` и `self.search_entry.set_text("")` (1868–1869); оба обработчика
(`on_search_mode` 1891, `on_search_changed`) вызывают `set_search("")` уже у новой страницы, а `search_text`
старой не трогают. Воспроизводится для всех четырёх списковых страниц.

### 3. ВАЖНО — Иконки отсутствуют в темах: «Горячие клавиши» в Yaru, «Служба PuLinTo» в Adwaita

Факт (а): в теме заказчика `Yaru-dark` (`gsettings get org.gnome.desktop.interface icon-theme`) имя
`preferences-desktop-keyboard-shortcuts-symbolic` (строка 1685, иконка раздела «Горячие клавиши») резолвится в
`/usr/share/icons/Yaru/16x16/status/image-missing.png` — `Yaru-dark` наследует `Yaru,Humanity,hicolor`, а не Adwaita,
где иконка лежит в `symbolic/legacy/`. На настоящем рабочем столе этот пункт боковой панели будет с «битой» картинкой.
Факт (б): в теме Adwaita (GTK 4.22, Xvfb) нет `emblem-ok-symbolic` (строка 1049) — строка «Служба PuLinTo — Работает»
показывает заглушку `image-missing` (`01-initial.png`, увеличено в `zoom-health-icon.png`). Это же случится на любом
GNOME без Yaru (Fedora, Debian/GNOME).
Ожидалось: иконки из набора, который есть в обеих темах (например `input-keyboard-symbolic`/`emblem-default-symbolic`
или `object-select-symbolic`/`checkbox-checked-symbolic`), либо встроенные ресурсы.
Проверка: `Gtk.IconTheme.lookup_icon` на :91 с `gtk-icon-theme-name = Yaru-dark` и Adwaita.

### 4. МЕЛОЧЬ — Текст окна называет режим «Только по Alt», хотя на PC-клавиатуре одиночный Alt ничего не делает

Факт: «Обзор» — «Выключите, и раскладку будете менять только вы — клавишей Alt.» (строка 989),
«Только по Alt»/«…раскладку меняете вы клавишей Alt.» (1036–1037); «Приложения» — режим «Только по Alt» (729),
подсказка в диалоге «Автоматически — исправления и Alt… Полностью выключено — PuLinTo не обрабатывает Alt.»
По `GetHotkeys` и `docs/MANUAL.md` («Почему в PC нет одиночного Alt») для PC-набора по умолчанию одиночный Alt не
назначен (Pause или правый Ctrl). У заказчика подключены две PC-клавиатуры (solaar-keyboard, Logitech K520) — на них
обещание «клавишей Alt» ложное. Трей (по MANUAL) тот же режим называет «Не трогать»/«Только по Alt».
Ожидалось: формулировка без привязки к Alt («по горячей клавише»), как уже сделано в описании действия
`toggle_app` на странице «Горячие клавиши» («…только по горячей клавише…»).

### 5. МЕЛОЧЬ — Ошибка валидации одна на все случаи и показывается только после «Сохранить»

Шаги: «Не менять» → «Добавить слово» → «ab» (2 символа). Факт: «Сохранить» активна (`dialog.require` на 664 проверяет
только непустоту); после нажатия демон вернёт `false` (`MIN_WORD_LEN = 3`, `crates/pulinto-core/src/exceptions.rs:35`)
и окно покажет общий текст «Правило не сохранено. Проверьте, что поля заполнены; слово для списков раскладки — минимум
3 символа.» (651). Тот же текст появится при табуляции/переводе строки в значении (демон отвергает их в
`autocorrect.rs:268`, а поля `Adw.EntryRow` принимают вставленный `\t` — подтверждено `05-dlg-unicode.png`,
`gettext` вернул `'… tab\there'`) и при любой другой причине. Для «Приложения» — просто «Правило не сохранено.» (879).
Ожидалось: проверка длины и управляющих символов до активации «Сохранить» (как в `validate_payload` для импорта,
где `\t\r\n` отвергаются явно) и конкретная причина в сообщении. (Не нажималось — поведение выведено из кода.)

### 6. МЕЛОЧЬ — Расхождения со `docs/MANUAL.md`

- MANUAL «Окно настроек»: «В окне семь страниц» — страниц восемь (перечислены тоже восемь: Обзор, Автозамены,
  Не менять, Всегда менять, Приложения, Клавиатура, Горячие клавиши, Справка).
- MANUAL: «Автоматически выученные правила отмечены в колонке «Источник»» — колонки нет; в окне это чип «выучено»
  и подсказка по наведению (строки 486–488, 498). Текст руководства устарел.
- MANUAL «Горячие клавиши»: варианты выбора набора названы «Авто», «Всегда Apple», «Всегда PC»; в окне —
  «Авто — по клавиатуре», «Всегда набор Apple», «Всегда набор PC». Терпимо, но при поиске по документации не сойдётся.
- «Справка» в окне называет действие «Исправить слово» (строка 1618), а страница «Горячие клавиши» (названия из
  демона) — «Сменить раскладку слова»; «Только выделенный текст» против «Переложить выделенный текст»;
  «PuLinTo в текущем приложении» против «Включить или выключить в приложении». Один и тот же набор действий под
  разными именами в двух соседних разделах. Привязки в «Справке» захардкожены (1613–1640) и не обновятся,
  если пользователь их поменяет — помечены «по умолчанию», так что не ошибка, но путаница.

### 7. МЕЛОЧЬ (с побочным эффектом в тесте) — Экспорт/импорт идут через xdg-portal, ошибки портала глотаются молча

Шаги: меню → «Экспорт правил…». Факт: на :91 никакого диалога не появилось (`18-export-dialog.png`), зато в
`org.freedesktop.portal.Desktop` появился запрос `/org/freedesktop/portal/desktop/request/1_19075/gtk1790922479` —
GTK 4.22 отдал выбор файла `xdg-desktop-portal-gnome`, который рисует диалог в настоящей сессии GNOME (за экраном
блокировки). Закрыть его извне нельзя (`Request.Close` → `AccessDenied: Unmatched caller`); запрос исчез вместе с
закрытием окна (проверено: после выхода `1_19075` в дереве портала нет). Для обычного пользователя это штатное
поведение, но в коде `_export_chosen`/`_import_chosen` (2043, 2061) любая `GLib.Error` трактуется как «отменил», в
том числе сбой портала/отсутствие бэкенда — пользователь нажмёт «Экспорт» и ничего не увидит.
Ожидалось: `error.matches(Gtk.DialogError.quark(), Gtk.DialogError.DISMISSED)` → тихо, остальное — `alert(...)`.
Отдельный тест `fdtest.py` на :91 подтвердил: `Gtk.FileDialog.save` 12 с не возвращает ни результата, ни ошибки.

### 8. МЕЛОЧЬ (статика) — Блокирующие вызовы D-Bus в главном потоке

- `Daemon.call` → `call_sync` с таймаутом 5 с (85); `refresh_all` (1927) делает 11+ синхронных вызовов подряд, а
  для «Всегда менять» — ещё по одному `PreviewLayoutConversion` на каждую строку (537): при N правилах N+1 вызовов
  на каждое обновление, включая после каждого сохранения/удаления.
- Предпросмотр «Станет» (679–684) — синхронный вызов на каждый символ ввода.
- `connect_or_start_daemon` (91–133): `time.sleep(0.1)` × 30 и `subprocess.Popen(pulintod)` до создания окна; при
  зависшем демоне окно не появляется до 5 с (таймаут) + 3 с. Также окно само запускает `pulintod`, минуя
  `systemctl --user` — при установленном юните второй экземпляр завершится сам по блокировке (MANUAL), но
  пользователь получит окно «не зарегистрировался в D-Bus» без объяснения.
- `wait_for_restart` (1977): синхронные `Status` по таймеру — приемлемо.
В сеансе (пустые списки, демон отвечает мгновенно) ни зависаний, ни задержек не было; на больших списках и
медленном демоне интерфейс будет замирать. Обработка «демон пропал» есть (`@guarded` → `daemon_failed`, 1917,
один алерт на серию ошибок) — на живом демоне не проверялась, статически корректна.

### 9. МЕЛОЧЬ (статика) — Устаревший API GTK

`Gtk.StyleContext.add_provider_for_display` (2210) объявлен deprecated с GTK 4.10; замена —
`Gtk.style_context_add_provider_for_display(display, provider, priority)` (та же функция, не через класс).
Предупреждения в stderr это не даёт (PyGObject не предупреждает о deprecated-функциях C), поэтому в
`gui-stderr.log` его нет. Остальной API (Adw.Dialog, AlertDialog, NavigationSplitView, Breakpoint, Gtk.FileDialog,
`load_from_string`) актуален для adw 1.9/GTK 4.22. Предупреждения `PyGIDeprecationWarning: GLib.unix_signal_add_full`
и `asyncio.*Policy` приходят из самого PyGObject 3.56 на Python 3.14, не из кода окна.

### 10. МЕЛОЧЬ — Доступность

Пункты боковой панели для AT-SPI безымянные (`[list item] ''`), имя несут вложенные метки; иконки без имени;
пункты меню `Gio.Menu` тоже видны как `[menu item] ''`. Скринридер прочитает текст, но «кнопка Меню → пункт 3» не
назовёт. Поля `Adw.EntryRow` дают имя дважды («Что набрано Что набрано») — особенность libadwaita.
