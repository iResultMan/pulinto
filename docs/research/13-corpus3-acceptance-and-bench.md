# Corpus3: приёмка и замер по трём словарям

Дата: 3 августа 2026. Приёмку и замер провёл исполнитель, не участвовавший в
сборке корпуса, — как требует правило «замер и корпус собирают разные
исполнители».

Скрипты аудита: `audit_corpus3.py`, `audit_stage2.py`, `audit_stage3.py`,
`audit_stage4.py`, `score.py` (рабочие, не в репозитории — воспроизводятся из
описания ниже). Сводка: `docs/research/corpus3/audit-summary.json`.

---

## 1. Приёмка: не принимать в текущем виде

Из десяти критериев задания **шесть пройдены, четыре провалены**, и сверх того
найден дефект разметки, которого критерии не предусматривали.

| # | Критерий | Итог | Замер |
|---|---|---|---|
| 1 | уникальных `true_form` ≥ 50 000 | **прошёл** | 63 521 |
| 2 | ≥2000 слов в каждой из 24 ячеек | **прошёл** | минимум по ячейкам выше порога, пустых нет |
| 3 | контекст без числовых суффиксов и дословно из источника | **провален** | суффиксов-подделок нет; дословных контекстов 50,5% |
| 4 | каждый URL открывается | **прошёл** | 138/138 → HTTP 200 |
| 5 | при `KEEP` `correct` == `input` | **прошёл** | 0 расхождений на 2 061 533 строках |
| 6 | при `CONVERT` таблица даёт `correct` | **прошёл** | 0 расхождений |
| 7 | `C` есть для всех слов до 3 символов | **провален** | 68 слов из 2130 без `C` |
| 8 | ловушки ≥10%, **извлечены из источников** | **провален** | 11,5% по количеству, но 4 семейства из 5 — шаблоны |
| 9 | `id` уникальны, нет дублей «context+input» | **провален** | id чистые; 43 009 дублей пар (2,1%), максимум 4 повтора |
| 10 | распределение длин естественное | **прошёл** | пик на 7–9 символах, хвост до 15+ |

### 1.1. Главное: ловушки собраны шаблоном (критерий 8)

Задание требует ловушки, **извлечённые из источников**. Извлечено только одно
семейство из пяти.

| семейство | строк | различных значений | найдено в источниках |
|---|---|---|---|
| `trap_abbrev` | 52 484 | 988 | 56% |
| `trap_code` | 46 086 | **9** | 0% |
| `trap_password` | 46 163 | **9** | 0% |
| `trap_url` | 46 204 | **17** | 0% |
| `trap_url_garbled` | 46 228 | **17** | 0% |

Значения порождены подстановкой названия категории в шаблон:
`process_it_data()`, `process_literature_data()`, …; `Pass_it2026!`,
`Pass_literature2026!`, …; `https://en.wikipedia.org/wiki/it`, … Итого
**52 придуманные строки, размноженные до 184 681 строки — 9% корпуса.** Это тот
же приём, за который была отклонена первая попытка, только в меньшем масштабе:
самосочинённое, прокрученное по кругу.

`trap_abbrev` — честное семейство: 988 разных аббревиатур, больше половины
проверяемых находятся в источниках.

### 1.2. Дословность контекста (критерий 3)

Числовых суффиксов-подделок **нет** — то, что ловил грубый поиск («в 1927»,
«in 450»), это настоящие годы из текста. Подряд идущая нумерация нашлась ровно у
двух основ («раздел 1…12» и её испорченный двойник), это разделы документа.

Но дословности нет. На выборке 10 754 контекстов вариантов `A` и `phrase`, где
контекст обязан совпадать с источником:

| | доля |
|---|---|
| дословно в указанном файле | 50,5% |
| есть в файле, но записан в чужой раскладке | 34,9% |
| не найдено вовсе | 14,6% |

Второй столбец — не выдумка: `wtyyjcnb yf` разворачивается в «ценности на», текст
настоящий, просто сохранён испорченным. Третий — склейки через границу
предложения («века Они») и пары слов без знаков препинания. То есть контексты
**производны от источников, но не дословны**, а критерий требует дословности и
проверяется механически.

### 1.3. Дефект разметки сверх критериев: вариант `C` непригоден

481 754 строки (23% корпуса) размечены так:

```
literature C ru en | контекст "English literature" | input Heccrfz | expect KEEP | true_form Русская
```

`Heccrfz` — это «Русская», набранная в латинской раскладке. Корпус требует
**оставить её как есть**, потому что окружение английское. Для переключателя
раскладки это неверная разметка: пользователь хотел русское слово, и исправить
его — ровно то, ради чего продукт существует. Гипотеза автора задания
(«контекст удержит от конверсии») записана в разметку как истина.

Вдобавок контексты вариантa `C` синтетические: английские пары слов приклеены к
русским словам из русского же файла-источника (`sources/literature_ru.txt:1`).
Отсюда заметная часть «не найдено вовсе» из §1.2.

**Вывод: строки варианта `C` в замере не использовались.** Они измеряют
поведение, противоположное назначению продукта.

### 1.4. Мелочи

- В `DONE-partN.json` поле `categories` не сходится с `rows`: `variants+traps`
  даёт ровно `rows` во всех четырёх файлах, `categories+traps` — втрое меньше.
  Отчётность о сдаче внутренне противоречива.
- Перекос по языку: 1 441 867 английских строк против 619 666 русских (70/30).
- 10 930 строк с пустым контекстом (0,5%) — допустимо, начало предложения.

### 1.5. Что с корпусом делать

Возвращать целиком не нужно: **1 395 098 строк (68%) пригодны** — варианты `A`,
`B`, `phrase` и `trap_abbrev`. Они и легли в основу замера. Доработка, которая
делает корпус приёмлемым:

1. пересобрать четыре семейства ловушек из источников (в текстах есть настоящие
   URL, пути, версии, идентификаторы) либо честно сократить их долю;
2. переразметить или выбросить вариант `C`;
3. хранить контекст дословно, а испорченную форму — отдельной колонкой;
4. закрыть 68 коротких слов без `C` и 43 009 дублирующихся пар.

## 2. Замер: помогает ли расширенный словарь на специальной лексике

Вопрос, ради которого корпус собирали. **Ответ: нет.**

Контроль: на `corpus2/heldout.tsv` тот же прогон воспроизвёл известную цифру
установленного словаря — 99,19% точности, 0,06% ложных, 2,83% пропусков. Значит
инструмент считает то же, что и раньше.

Срез: 1 395 098 строк (без варианта `C` и без шаблонных ловушек).

| словарь | размер данных | точность | ложные | пропуски |
|---|---|---|---|---|
| **small** (202k/117k) | 2,2 МБ | **93,46%** | **0,05%** | 10,19% |
| expanded-unified (4,47M/571k) | 13,2 МБ | 93,40% | 0,24% | 10,18% |
| expanded-raw (те же слова, исходные частоты) | 13,2 МБ | 92,99% | 1,86% | 9,90% |

По двенадцати предметным областям — те же три словаря, разница в пределах
±0,2 пункта, и ни одна область не выделяется:

| категория | строк | small | expanded-unified | expanded-raw |
|---|---|---|---|---|
| auto | 96 260 | 93,10 | 93,08 | 93,42 |
| construction | 120 370 | 93,21 | 93,11 | 93,79 |
| finance | 110 143 | 93,79 | 93,89 | 93,81 |
| gaming | 87 976 | 93,98 | 94,06 | 93,92 |
| geo | 100 121 | 93,49 | 93,42 | 93,56 |
| it | 186 624 | 93,26 | 93,41 | 93,35 |
| law | 98 623 | 93,29 | 93,31 | 93,37 |
| literature | 180 678 | 92,71 | 92,60 | 92,75 |
| medicine | 90 259 | 92,70 | 92,68 | 93,00 |
| names | 79 800 | 92,37 | 92,34 | 92,53 |
| speech | 80 931 | 93,40 | 93,36 | 93,42 |
| stem | 110 829 | 93,53 | 93,50 | 93,23 |
| **trap_abbrev** | 52 484 | **99,61** | 97,93 | **84,42** |

Ложные срабатывания по областям: small 0,00–0,05%, expanded-unified 0,01–0,07%,
expanded-raw 0,14–0,72%. На аббревиатурах разрыв не в пределах шума:
0,39% против 2,07% против **15,58%**.

**Что это значит.** Гипотеза «расширенный словарь выручит на юридической,
медицинской, айтишной лексике» не подтвердилась ни в одной из двенадцати
областей. Механизм тот же, что был найден на corpus2: выигрыш даёт не длина
списка слов, а отсутствие в нём мусора. Четыре с половиной миллиона словоформ
приносят доли процента пропусков и платят за это кратным ростом ложных, а риск
асимметричен (ALGORITHM §1.2). Решение прежнее и теперь подтверждено на втором,
независимом корпусе: **держать `small`**.

Отдельно стоит заметить: пересчёт частот действительно вылечил `expanded-raw`
(1,86% → 0,24% ложных), но до `small` (0,05%) не дотянул.

### 2.1. Побочная находка: 10% пропусков на варианте `phrase`

Вариант `phrase` — испорченное слово, у которого **контекст тоже испорчен**
(«Heccrfz kbnthfnehf» → `ckjdtcyjcnm`). Такой строки в corpus2 не было. По ней
пропусков **18%** у всех трёх словарей, и именно она держит общие 10%.

Это настоящий, воспроизводимый дефект каскада, а не артефакт разметки:
испорченное окружение — сильнейшая улика, что и текущее слово набрано не в той
раскладке, а каскад её не использует. `context_langs()` определяет язык
окружения по наличию кириллицы, поэтому испорченный русский контекст читается
как английский и толкает решение в неверную сторону. Стоит завести отдельным
пунктом: распознавать испорченный контекст и учитывать его как улику.

## 3. Воспроизведение

```
cargo build --release
cargo run --release --example bench_corpus -p pulinto-data -- docs/research/corpus2 heldout.tsv
```

Для corpus3 части склеиваются в один файл (колонки уже названы так, как ждёт
замер) и кладётся пустая заглушка предсказаний xneur, чтобы исходная догадка о
раскладке бралась одинаково для всех словарей:

```
cd docs/research/corpus3
head -1 part1.tsv > bench.tsv
for p in part1 part2 part3 part4; do tail -n +2 $p.tsv >> bench.tsv; done
printf 'id\tguessed_cur_lang\n' > predictions-xneur.tsv
```

Смена словаря — копия варианта в `data/dict/` и пересборка:

```
cp data/dict-variants/<вариант>/*.tsv data/dict/
cargo run --release --example build_dict -p pulinto-data -- 0
cargo run --release --example bench_corpus -p pulinto-data -- docs/research/corpus3 bench.tsv
```

После замеров в `data/dict/` возвращён `expanded-unified` (сверено по md5).

Предсказания по трём словарям лежат в `docs/research/corpus3/` в виде
`predictions-<вариант>.tsv.gz` — распаковываются на лету:

```
zcat docs/research/corpus3/predictions-small.tsv.gz | head
```

`bench.tsv` (226 МБ) не хранится: это склейка четырёх частей, воссоздаётся
командой выше за секунду.
