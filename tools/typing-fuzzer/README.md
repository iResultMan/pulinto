# Стенд-машинистка

Робот, который печатает по-настоящему — через uinput, теми же скан-кодами, что и
живая клавиатура, — и помнит, что именно хотел набрать. Нужен потому, что
дефекты исполнения видны только вживую, а человек не может ни печатать часами,
ни вспомнить потом, какую клавишу нажал.

## Почему не `xdotool`

`xdotool` и всё, что стоит на XTEST, вставляет события на другом уровне: в
`/dev/input` они не появляются, а демон читает именно оттуда. Стенд на XTEST
измерял бы тишину и рапортовал об успехе.

По той же причине устройство машинистки называется `PuLinTo Test Typist`:
демон исключает из перехвата только **своё** устройство, по имени.

## Из чего состоит

| | |
|---|---|
| `src/typist.rs` | печатает слова из настоящего текста, между словами произвольно меняет раскладку, пишет в лог что хотел, чем набрал и какими кодами |
| `sink.py` | окно-приёмник: записывает полное содержимое поля после каждого изменения — по нему видно потерю, дублирование и уехавший текст |
| `compare.py` | сверяет три лога |

## Эталон

Простой и потому надёжный: **что бы ни было набрано, на экране должно оказаться
слово в его родном виде.** Набрано в своей раскладке — демон обязан не трогать;
набрано в чужой — обязан починить. Итог один, и сверять есть с чем.

Отдельно считается то, что решает всё: **не исправлено** (текст цел, демон не
справился) против **испорчено** (на экране то, чего пользователь не набирал).
Второе недопустимо, первое — терпимо.

## Запуск

```bash
cargo build --release                       # в корне проекта
cd tools/typing-fuzzer && cargo build --release
```

Стенд занимает экран и клавиатуру: за машиной в это время работать нельзя.
Порядок важен — **устройство должно появиться раньше демона**, потому что демон
перечисляет клавиатуры один раз при старте:

1. запустить `typist --wait 20` (создаёт устройство и ждёт);
2. поднять демон;
3. открыть `sink.py` и **убедиться, что окно в фокусе** — иначе нажатия уйдут
   мимо, лог демона будет выглядеть здоровым, а сверять будет не с чем;
4. дождаться конца и прогнать `compare.py`.

Готовый сценарий с проверкой фокуса и сторожем, снимающим захват по таймеру, —
в рабочих записях сессии (`run.sh`).

## Две ступени проверки: эталон и бой

Эталон отвечает на вопрос «что изменила правка»: один и тот же набор, те же
seed, цифры до и после. Веб-блок отвечает на вопрос «как это работает в бою»:
каждый раз новые тексты из интернета. Любая правка сначала идёт на эталон (не
хуже — иначе разбор), потом на свежий веб-блок (решение заказчика, 18 октября
2026). Эталон на `12c640172cbc`:

| проверка | команда / сценарий | эталон |
|---|---|---|
| heldout corpus2, 21 300 слов | `cargo run --release --example bench_corpus -p pulinto-data -- docs/research/corpus2 heldout.tsv` + `score.py` | 99,37 % / 8 ложных / 126 пропусков |
| стенд 600, ru(mac) | `OVERLAP=30 SHUFFLE=25 SEED=301 run-script.sh … script-600.txt 100 6 virtual` | 598 / 1 / 0 / 1 |
| стенд 600, обычная ru | то же, `VARIANTS="us=,ru=" SOURCES="[('xkb', 'us'), ('xkb', 'ru')]"` | 598 / 2 / 0 / 0 |
| блок IT, 20 000 слов | `SEED=412 run-script.sh … genre-it.txt 100 6 virtual` | 19769 / 190 / 1 / 26 (без артефактов нагрузки 24 порчи) |
| обычная ru, 10 000 слов | `SEED=303 … script-10000.txt`, `VARIANTS`/`SOURCES` как выше | 9899 / 97 / 3 / 1 |
| веб-сценарий 2026-10-18-1443, 20 000 слов (замороженный) | `SEED=19018 run-script.sh … scripts/web-2026-10-18-1443.txt 100 6 virtual` | 19803 / 186 / 1 / 8 (на `12c6`; `Вуджек` после правки должен остаться) |
| живой Wayland | `FORCE=1 python3 -I tools/live-wl-test/selection_check_wl.py` | 21 / 0 |
| X11-харнесс, хоткеи, хаос | `selection_check.py`, `run-hotkeys.sh`, `run-chaos.sh 40 1` | 14 / 0, 168 / 0, 40 / 0 |

Первый веб-сценарий `scripts/web-2026-10-18-1443.txt` после прогона тоже
входит в эталон как «боевой текст с замороженным seed»; следующие веб-блоки
эталон не меняют, они — бой.

## Веб-блок: свежие тексты каждый раз

Сценарии из корпуса 3 и жанровые блоки — это слова, которые мы уже знаем; на
одном и том же наборе результат застывает на своих 98–99 % и перестаёт быть
оценкой. Поэтому боевой блок пересобирается заново при каждом прогоне из
произвольных статей интернета (решение заказчика, 18 октября 2026):

    tools/typing-fuzzer/web-block.sh [слов=20000] [пауза=100] [выдержка=6]

1. `fetch_web_sources.py` качает тексты по семи тематикам на двух языках —
   новости (lenta, ria | BBC), IT (habr | The Verge, BBC Technology), наука
   (nplus1, Википедия | BBC Science, Wikipedia), бизнес (rbc | BBC Business),
   спорт (sports.ru | BBC Sport), литература (ru/en Викитека, случайные
   страницы), разговорный (pikabu, dtf | комментарии Hacker News) — в
   `docs/research/corpus-web/<метка>/sources/*_{ru,en}.txt`; `manifest.json`
   хранит адреса страниц, счётчики слов и seed. Сами тексты в git не идут
   (чужие и одноразовые), манифест и сценарий — идут.
2. `make_script.py --sources` режет их на сценарий `scripts/web-<метка>.txt`:
   куски по 3–25 слов, язык меняется между кусками, 60 % русского. С
   `--hard-share natural` (так делает `web-block.sh`) внутрь кусков своего
   языка подмешиваются **трудные токены** в той доле, в какой такие слова
   есть в самих текстах (18 октября: ru 2,2 %, en 4,3 %). Берутся они из
   рукописного пула `tools/typing-fuzzer/hard-tokens.txt` — написан по
   классам, а не собран из текста (решение заказчика): сокращения с точкой
   (`т.е.`, `e.g.`), инициалы, домены и файлы (`site.ru`, `main.py`), цифры
   (`2020-х`, `COVID-19`), апострофы (`don't`), знаки `; : ! ? ( ) "` на
   концах, дефисные, аббревиатуры, буквы на знаковых клавишах (`объём`,
   `нейрокомпьютеры`), ё, короткие и спорные (`her`, `рук`), код (`C++`,
   `snake_case`), смешанный регистр (`iPhone`). Строгий фильтр всё это
   отбрасывал, и стенд не видел ровно те классы, под которые писались правила
   (ревью, раздел 20). `--hard-pool harvested` подмешивает вместо пула
   токены, собранные из текстов; `--hard-list` пишет их список с классами.
   Не набираются одной раскладкой и пропускаются: смешанные алфавиты
   (`USB-порт`, `сайт.ru` — в пуле с языком `mixed`, их проверяет живой
   Wayland-харнесс) и знаки вне раскладки («», —). `--hard-share 0` даёт
   прежний чистый сценарий — эталонные сценарии такие.
3. `run-script.sh` прогоняет сценарий на виртуальном стенде со случайным
   `SEED` (25 % слов в чужой раскладке, перекрытие 30 мс); дежурный демон
   снимается на время прогона и поднимается в конце.

Воспроизвести конкретный блок: `FETCH_SEED`, `SCRIPT_SEED`, `RUN_SEED` из
`manifest.json`, имени сценария и `history.tsv` (тексты в интернете к тому
времени другие — воспроизводится сценарий, не сбор). Ошибки прогона
разбираются как у жанровых блоков: `errors.tsv`, трассы, `pair.py` не
применим (набор каждый раз новый) — сравнивать доли, не слова.

## Что стенд уже нашёл

- разделитель печатался раньше, чем возвращалась раскладка: `Русская.` выходило
  `Русскаяю`;
- демон перечисляет клавиатуры только при старте — Bluetooth-клавиатура после
  переподключения становится невидимой навсегда;
- порог скорости набора, за которым режим наблюдения перестаёт справляться.
